Privacy Policy

HeyVox and the Hush Chrome extension · Last updated: 3 July 2026

This policy covers both HeyVox, the desktop voice layer for AI coding agents, and Hush, the companion Chrome extension that pauses in-browser media while HeyVox is speaking or listening. The short version: by default, nothing you do with either product is sent anywhere. Two optional features — anonymous telemetry and vocabulary learning — are off by default and only send data if you explicitly turn them on; both are described below.

Summary

By default, HeyVox and Hush run entirely on your Mac: no analytics, no telemetry, no ads, no user accounts, and no data sent to any server. Your microphone audio never leaves your device under any configuration. Two optional features are off by default and only transmit data if you explicitly enable them:

  • Anonymous telemetry — if you opt in, HeyVox sends a version string, a hashed (non-identifying) hostname, and five numeric counters to heyvox.dev. No transcripts, log lines, file paths, or configuration values are ever included.
  • Vocabulary learning — if you opt in and run heyvox learn-vocab, recent dictation transcripts (text, not audio) are sent to the Anthropic API to improve recognition of your custom terms.

Both are disabled unless you turn them on, and both fail closed — any doubt about your consent means nothing is sent.

Data we collect

No account, no signup, no login. By default, no usage reporting either: HeyVox runs entirely on your Mac, and Hush inside your copy of Chrome plus a local companion process. The only data that ever leaves your Mac is through the two opt-in features described in the summary above (anonymous telemetry and vocabulary learning), both off by default.

Audio, speech, and transcription

  • Wake-word detection runs locally on-device via openwakeword.
  • Speech-to-text runs locally on-device via MLX Whisper (Apple Silicon) or sherpa-onnx (Intel).
  • Text-to-speech runs locally on-device via Kokoro or Piper.
  • No audio ever leaves your device, under any configuration.
  • Transcripts, model outputs, and training data also stay on your device — unless you opt into vocabulary learning (heyvox learn-vocab), which sends recent dictation transcripts (text only, never audio) to the Anthropic API. This is off by default; when it is off, nothing is shared with Anthropic, OpenAI, Google, Apple, or anyone else.
  • A local transcript history is stored in ~/.config/heyvox/ on your Mac. Deleting that file or the config directory removes it.

Browser data (Hush extension)

Hush reads the tab.audible property of tabs to find which one is producing audio, and executes a small pause/resume script against the matching tab. Hush does not:

  • Read tab content, page HTML, form contents, passwords, cookies, or any other page data.
  • Read or store URLs, titles, or browsing history.
  • Send any data over the network.

The <all_urls> host permission is used only because media can play on any site. The extension does not examine or transmit anything about the sites you visit.

Native messaging

Hush talks to its desktop companion via Chrome's standard nativeMessaging API. This is a process-to-process channel on your local machine — it does not reach the internet. Messages contain only pause/resume commands and acknowledgements; no user content is exchanged.

Model downloads

First-time setup downloads speech-recognition and text-to-speech models from their respective open-source repositories (Hugging Face, GitHub). These are one-off downloads directly from those hosts — we do not proxy them, log them, or see that they happened. You can audit the download URLs in the source code at github.com/heyvox-dev/heyvox.

Analytics, crash reporting, telemetry

HeyVox includes optional, off-by-default anonymous telemetry. When it is disabled (the default), nothing is sent. When you explicitly opt in — during setup, or via config — HeyVox periodically sends to heyvox.dev: the HeyVox version, macOS version, Mac model, Python version, a hashed non-identifying hostname, and five numeric event counters (e.g. wake-word drops, mic restarts). It never sends transcripts, log-line content, file paths, or configuration values. You can preview the exact payload with heyvox telemetry preview and turn it off at any time (or set HEYVOX_TELEMETRY=0). There is no crash reporter phoning home — stack traces stay on your Mac.

Third parties

By default we share no data with third parties. The one exception is the opt-in vocabulary-learning feature: only when you enable it, recent dictation transcripts are sent to the Anthropic API (processed under Anthropic's terms) to improve recognition of your custom terms. The open-source speech and text-to-speech models (Whisper, Kokoro, Piper, openwakeword, sherpa-onnx) run entirely on your device and are licensed under their respective open-source licences.

Children's privacy

HeyVox and Hush are developer tools not directed at children under 13. Because we do not collect any personal data, we do not knowingly collect data from children or anyone else.

International users / GDPR / CCPA

By default, HeyVox and Hush do not collect personal data, so there is no personal data subject to cross-border transfer, access, or deletion requests. If you opt into telemetry, the only identifier stored is a hashed hostname that cannot be reversed to your identity; if you opt into vocabulary learning, transcripts are processed by Anthropic under their terms. You are welcome to delete the applications, the Chrome extension, and the ~/.config/heyvox directory at any time, and to leave both opt-in features off (their default).

Changes to this policy

If we ever materially change how HeyVox or Hush handles data, we will update this page and the "Last updated" date at the top. Since the software is open-source, any such change would also be visible in the public repository's commit history at github.com/heyvox-dev/heyvox.
