<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → PyPI | OIDC JWT crosses this boundary; signed by GitHub's identity provider, verified by PyPI |
| `pyproject.toml` → install-time dependency resolution | Untrusted PyPI mirror could theoretically swap a dep; mitigated by sha256 in lock-equivalent practice (out of scope for v1) |
| Repo `main` branch → `.github/workflows/publish.yml` → PyPI publish | Anyone with write access to workflow file path can redirect uploads |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-02 | Tampering / Elevation of Privilege | `.github/workflows/publish.yml` | mitigate | OIDC trusted publisher binds to specific workflow file path + environment name + tag-only trigger; `id-token: write` scoped to publish job only. Anyone tampering with publish.yml would need to push to main, which requires branch protection (recommended but maintainer-only enforcement at this scale). actionlint step in ci.yml additionally catches syntax-level tampering attempts that would otherwise pass review. Severity: medium (any compromise of main can publish, but main is a solo repo). |
| T-14-02b | Spoofing | OIDC token exchange | mitigate | Delegated to pypa/gh-action-pypi-publish@release/v1 — JWT verification handled by maintained library. No hand-rolled crypto. |
| T-14-01 | Tampering | Future hey_vox.onnx download (NOT in this plan; addressed in 14-04) | n/a here | Out of scope for 14-01 — see 14-04 threat model |
