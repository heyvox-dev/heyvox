    ```markdown
    # Training Your Own "Hey Vox" Wake Word

    HeyVox ships with a general-purpose "Hey Vox" wake-word model that works for
    most voices out of the box. If detection is unreliable for your voice, your
    accent, or in your noise environment, you can retrain the model with your
    own samples. This doc walks the Colab path (recommended, ~1 hour, free GPU)
    and points at the local pipeline for hands-on debugging.

    ## Why retrain?

    The shipped model is trained on diverse synthetic + real-voice samples and
    passes the ship gate (TP ≥ 70%, FP < 1/hour). But your voice / accent /
    background-noise profile may not be in the training set. Retraining locks
    your samples into the model so detection becomes far more reliable for *you*.

    ## What you'll produce

    A new `hey_vox.onnx` file that drops into `~/.config/heyvox/models/` and
    replaces the shipped model. HeyVox loads it on next restart — no other
    config changes needed.

    ## Quick path: Google Colab (~1 hour)

    The Colab notebook is the maintained ship pipeline. It runs on Colab's free
    T4 GPU and produces the exact format `openwakeword` expects.

    1. Open `training/hey_vox_colab.ipynb` in Google Colab
       ([direct link](https://colab.research.google.com/github/heyvox-dev/heyvox/blob/main/training/hey_vox_colab.ipynb))
    2. Runtime → Change runtime type → **T4 GPU**
    3. Run all cells. The notebook:
       - Generates synthetic positive clips via `piper-sample-generator` (diverse voices)
       - Pulls negative clips from Common Voice + LibriSpeech (Hugging Face datasets)
       - Trains the openwakeword MLP head on the combined corpus
       - Exports `hey_vox.onnx` for download
    4. Download `hey_vox.onnx` from the Colab file browser (right-click → Download)
    5. Drop it into the models dir:
       ```bash
       mkdir -p ~/.config/heyvox/models
       mv ~/Downloads/hey_vox.onnx ~/.config/heyvox/models/hey_vox.onnx
       heyvox restart
       ```

    ## Slow path: Local pipeline (~4 hours, no GPU needed but slow)

    For hands-on debugging, the local pipeline in `training/` runs end-to-end on a
    Mac. See `training/README.md` for the full walkthrough. The local pipeline is
    *experimental* — the Colab path is the ship pipeline.

    ## Validating before swapping in your new model

    Before you replace your `~/.config/heyvox/models/hey_vox.onnx`, run the
    ship-gate evaluator from this repo:

    ```bash
    python training/evaluate_model.py \
        --model ~/Downloads/hey_vox.onnx \
        --positives ~/heyvox-eval/test/real_voice/ \
        --negatives ~/heyvox-eval/test/fp_corpus/ \
        --sweep
    ```

    The script tries thresholds `[0.5, 0.6, 0.7, 0.8, 0.9, 0.95]` and reports the
    lowest one that satisfies both gates simultaneously:

    - **TP ≥ 70%** — at least 7 in 10 real "Hey Vox" utterances are recognized
    - **FP < 1 per hour** — fewer than one false trigger per hour of normal speech

    Exit code 0 means the model passed; exit code 1 means iterate.

    ### Assembling the test corpora

    - **Positive set** (`test/real_voice/`): your own "Hey Vox" recordings, plus held-out
      clips from [record.felberer.at](https://record.felberer.at) if available. Aim
      for 30-100 clips from at least 3 different speakers.
    - **Negative set** (`test/fp_corpus/`): general English speech. The openwakeword project
      publishes a standard validation corpus (DiPCo + Santa Barbara + MUSDB, ~11 hours
      total). Download it via the `prepare_validation_corpus` cell in the Colab notebook,
      or fetch directly:
      ```bash
      # Conceptual — see training/colab_hey_vox.py for the actual fetch commands
      python -m training.colab_hey_vox --prepare-fp-corpus --out test/fp_corpus/
      ```

    ## Tuning the threshold

    If the sweep recommends a threshold higher than `0.5` (the wake-word default),
    set it in your config so HeyVox uses it at runtime:

    ```yaml
    # ~/.config/heyvox/config.yaml
    wake_words:
      model_thresholds:
        hey_vox: 0.6  # or whatever the sweep recommended
    ```

    Raising the threshold reduces false positives at the cost of true positives;
    lowering it does the opposite. The ship gate is calibrated for the model
    HeyVox bundles by default — your retrained model may need a different sweet
    spot.

    ## Ship-gate methodology (for reference)

    The thresholds (TP ≥ 70% AND FP < 1/hour) are non-arbitrary — they're the
    benchmark openwakeword publishes for its own bundled models. A model that
    misses either gate would be either too noisy (interrupts users mid-sentence)
    or too dead (users say "Hey Vox" three times before it triggers). Both are
    bad UX. The gate keeps your retrained model on par with what ships by
    default.

    ## Related docs

    - [`training/hey_vox_colab.ipynb`](../training/hey_vox_colab.ipynb) — the Colab notebook itself
